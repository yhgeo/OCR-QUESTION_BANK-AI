# OCR-题库-AI

一个基于 Windows 截图的答题辅助工具：先对截图中的题目做识别，优先查询本地题库，未命中时再调用兼容 OpenAI 接口的大模型答题。

## 当前功能

- 支持仅题库模式：启动时可以跳过大模型配置，直接使用题库。
- 支持离线 OCR 识题：题库匹配依赖本地 OCR，不依赖联网模型。
- 支持题库优先 + AI 兜底：题库未命中时，优先使用 OCR 文本请求 AI，必要时再用截图图片兜底。
- 支持自动读取和保存模型配置。
- 支持显示最接近的题库题目及对应答案，便于补题和调试 OCR 命中效果。
- 支持窗口预览与区域预览；如果预览图保存失败，只会跳过保存，不会导致程序退出。
- 支持按窗口相对坐标设置截图区域，窗口移动后区域会跟随窗口更新。

## 运行环境

- Windows
- Python 3.10+（推荐 Python 3.10 或 3.11）

## 安装依赖

```bash
pip install -r requirements.txt
```

当前依赖见 `requirements.txt`：
- requests
- Pillow
- pywin32
- numpy
- rapidocr-onnxruntime

## 快速开始

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python answer_helper.py
```

如果你要提前写好模型配置，可以复制示例文件：

```bash
copy answer_helper_config.example.json answer_helper_config.json
```

然后把 `answer_helper_config.json` 里的 `api_key`、`base_url` 和 `model` 改成自己的配置。也可以不复制配置文件，直接运行程序并按提示填写。

## 启动方式

```bash
python answer_helper.py
```

也可以先做一次语法检查：


## 使用流程

1. 启动程序。
2. 选择是否启用大模型答题。
   - 选择否：会跳过大模型配置，并自动启用题库。
   - 选择是：可以读取已保存配置，或重新配置模型提供方、API Key、Base URL 和模型。
3. 如果启用了题库，可选择是否开启题库优先。
4. 可选设置固定窗口和截图区域。
5. 进入循环后，按回车截图识别：
   - 若题库可用，先使用离线 OCR 提取题目并查题库；
   - 若题库命中，直接输出题库答案；
   - 若题库未命中且模型可用，会优先使用 OCR 文本请求 AI；
   - 若 OCR 文本答题失败且不是模型不可用类错误，会再尝试用截图图片请求 AI；
   - 若题库未命中且模型不可用，则直接提示无法继续 AI 答题。
6. 循环中输入 `w` 可以重新选择窗口；切换窗口后，旧截图区域会被清空，需要重新设置固定区域。

## 截图窗口与区域

设置固定窗口后，程序会按窗口位置截图；如果继续设置截图区域，输入的是相对于窗口左上角的坐标，例如 `0,100,326,400`。窗口移动后，固定区域会按新的窗口位置自动换算；如果在运行中输入 `w` 切换窗口，原截图区域会被清空，需要重新设置。

## 题库文件说明

程序会从以下位置加载题库：
- `question_banks/*.json`
- `answer_question_bank.json`

仓库默认只保留示例题库：
- `question_banks/example.json`

你可以按相同结构新增自己的题库文件。单条题目示例：

```json
{
  "entries": [
    {
      "question": "示例题目",
      "answer": "示例答案",
      "aliases": ["示例别名1", "示例别名2"]
    }
  ]
}
```

字段说明：
- `question`：题目正文
- `answer`：答案
- `aliases`：可选，题目的别名或 OCR 常见误识别版本

为了降低误答风险，OCR 只识别到很短文本时不会直接按“包含关系”强制命中题库。如果经常未命中，可以把 OCR 常见识别结果补充到 `aliases` 中。

## 模型配置说明

程序运行时会读取并保存 `answer_helper_config.json`。

仓库额外提供了一个示例文件：`answer_helper_config.example.json`。你可以参考它的结构，或直接复制一份并命名为 `answer_helper_config.json` 后再填写自己的真实配置。

首次使用时也可以直接运行程序，按提示填写你的：
- 提供方名称
- API Key
- Base URL
- 模型 ID

注意：
- 不要把你自己的真实 `answer_helper_config.json` 或 API Key 上传到 GitHub。
- 示例文件中的 `api_key` 只是占位符，使用前需要替换为你自己的密钥。
- 目前支持 OpenAI 兼容接口；当提供方不支持 `/models` 时，也可以手动输入模型 ID。
- 如果模型不支持图片输入，题库未命中时仍可优先使用 OCR 文本进行 AI 答题。

## 常见问题

### 找不到窗口怎么办？

先确认目标程序没有最小化，并且窗口标题能在列表里看到。如果列表里没有目标窗口，可以跳过固定窗口，先用全屏截图确认流程是否正常。

### OCR 识别不准怎么办？

尽量只截题目和选项区域，避免把无关文字一起截入。对于经常识别错的题目，可以把错误识别文本加入题库条目的 `aliases`。

### 题库未命中怎么办？

程序会显示最接近的题库题目和相似度。你可以根据这条提示补充题库，或增加对应题目的 `aliases`。

### 模型报错怎么办？

如果出现 401/403，请检查 API Key 和 Base URL；如果出现 429，请稍后重试或更换模型；如果模型不支持图片输入，可以依赖 OCR 文本优先答题。

## 已知限制

- 当前项目是 Windows 专用，依赖桌面截图和窗口枚举能力。
- 目标窗口不能处于最小化或隐藏状态，否则可能无法获取窗口位置或截图。
- 离线 OCR 的效果会影响题库命中率；必要时可通过补充 `aliases` 优化匹配效果。
- 过短 OCR 文本不会直接强制命中题库，以减少误答风险。
- 题库未命中时能否继续答题，取决于当前模型是否已正确配置并可访问。
- 预览图保存不是核心流程；即使保存失败，也不影响截图识别和答题主流程。
